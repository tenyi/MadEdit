## 1. 結論

1. **命令表已完整可用。** 176 個命令全部有實作並經由 `App::run` 派發（`src/app/actions.rs`），不存在選單中停用的佔位項目。
2. **功能完成度高於原版。** 原版 MadEdit 為 C++ / wxWidgets 移植版本，許多功能在非 Windows 平台失效；本專案以 Rust 重寫後，三種編輯模式、編碼無損處理、Markdown／Mermaid／LaTeX 預覽、dprint 格式化等項目是本專案獨有。
3. **仍未實作的只剩四類：**

   | 類別 | 具體項目 |
   |---|---|
   | 平台整合 | 檔案類型關聯（僅提供操作說明）、Windows shell 外掛 |
   | 排版進階 | 真正的 Unicode bidi（目前是鏡像版面）、跨行 Regex、程式碼摺疊、多游標／多重選取 |
   | 自動化 | 腳本引擎（目前是錄製式巨集）、HTML／XML 專用工具鏈（XML 樹狀檢視、lint、標籤自動完成、內建 HTML 預覽） |
   | 遠端 | FTP／SFTP／SSH 遠端檔案、Git 版控整合、檔案比較與合併（diff） |

4. **列印走瀏覽器。** 列印與「預覽為 HTML」都是把文件轉成 HTML 後交給系統瀏覽器列印；內建的預覽列印視窗只負責版面預覽，不直接驅動印表機。

## 3. 已知限制與設計決策

1. **列印**：文件轉成 HTML 後交給系統瀏覽器列印，好處是可用瀏覽器的紙張與縮放設定，限制是無法直接控制印表機。內建預覽列印視窗只呈現版面（頁首頁尾、分頁、頁碼）。
2. **HTML 預覽**：同樣交給系統瀏覽器，沒有內建瀏覽器，因此沒有「雙擊預覽跳回原始碼」與 DOM 定位。
3. **Regex**：行導向，無法跨行比對；取代語法支援群組引用。
4. **bidi**：「由右至左」為鏡像版面，未實作完整的 Unicode 雙向排版。
5. **巨集**：錄製式步驟清單，不含腳本語言，因此無法做條件判斷或迴圈。
6. **大檔**：超過 `max_text_file_mb`（預設 100 MB）的檔案以十六進位模式開啟，資料留在磁碟上依需求讀取。

## 4. 歷史：為什麼改用 egui（摘要）

2026-10-22 的原始盤點結論是「功能完成度約兩成」，且決定性需求是使用者可任選字型（含比例字型），這需要執行期逐字量測字寬：Slint 沒有公開這種 API，egui 的 `Galley` 則是原生能力，且量測與繪製共用同一條字型後備鏈。

完整評估、風險清單與遷移成本見 [ADR 0011](adr/0011-egui-rewrite.md)。該 ADR 的完成度結論為：165 個命令全部可用；介面語言可切換；仍未實作者為單一執行個體、檔案關聯、真正的 bidi、語法配色逐項自訂、跨行 Regex 與 Python 巨集。

截至 `40a7328`，上列項目中**單一執行個體已實作**（`src/single_instance.rs`），**Python 巨集改以 JSON 步驟清單取代**（設計決策而非缺口），其餘四項仍在缺口清單中。
